## 2. Running the suites and CI

```bash
npm run verify                        # lint + type-check + unit/component + Chromium E2E (builds the app)
npm test                              # unit + component only (writes reports/vitest.json)
npm run test:e2e                      # Chromium E2E against `next build && next start` on :3100
E2E_ALL_BROWSERS=1 npm run test:e2e   # Chromium + Firefox + WebKit
npm run traceability                  # regenerate sections 5–8 from reports/
```

Every test runs at a fixed instant (20 Nov 2026, 10:00 IST) against freshly generated seed data in `Asia/Kolkata`. Each E2E test also fails on any uncaught page error or `console.error`. The one exception is listed in `e2e/support/fixtures.ts`: WebKit's report of prefetch requests that a test navigation cancels. It was checked to occur only on cancelled requests, never while idle or during real navigation.

**CI.** `.github/workflows/frontend-tests.yml` runs on every PR and push to `main`/`develop`: lint, type-check, unit/component tests, then Chromium E2E. Nightly it runs Chromium, Firefox and WebKit. In CI a failing test fails the job. A test that only passes on retry also fails it (`failOnFlakyTests`), so a retry can't hide a regression. A negative check confirmed this locally: reverting one contrast token made the CI-mode run exit with code 1, failing both the attempt and the retry.

**Results in §5** come from a clean checkout of commit `41f6c75` on macOS (a detached worktree, fresh `npm ci`, no `.next`, Node 22.14.0, retries off), so they include the CI fixes below. In that run lint and type-check exited 0, Vitest passed 488 of 488, and Playwright passed 690 of 690 (230 tests × Chromium, Firefox and WebKit) with nothing flaky or skipped. That covers all 138 A11Y-007 contrast checks in each browser. The pull request's CI run is still the reference for Linux.

**Non-frontend TypeScript.** The root `tsconfig.json` includes `**/*.ts`, so TypeScript outside the frontend would break `npm run typecheck`, `npm run build` and `npm run test:e2e`. `design/` is excluded, which covers the Prisma starter in `design/studyverse-prisma-initial/` (its `prisma7.config.ts` imports `prisma/config`, which the frontend doesn't install). Exclude `apps/` the same way when the backend package is added.

**CI history**

1. Before the first push, a clean checkout of the commit found that `tsc` needs Next's generated route types, which a fresh checkout lacks. `typecheck` now runs `next typegen` first, as the Next 16 docs recommend.
2. The first CI run on the pull request failed on two problems that didn't show on macOS:
   - **EXAM-021 timed out.** The test advanced fake time 30 minutes tick by tick: 1,801 re-renders, 3.1 s locally and over the 5 s limit on the 2-core runner. It now jumps to 3 s before the deadline and lets real ticks cross zero (10 ms). The auto-submit path is unchanged.
   - **RESP-007 found the signed-in header 5 px too wide at 390 px** under Linux font metrics. That was a real bug: the header overflowed on any OS below about 389 px. It is fixed (§9). The responsive suite now also checks 360 px, plus WCAG 1.4.10 reflow at 320 px on every route, and overflow failures name the offending elements.
3. Before pushing, the fixes passed lint, typecheck, the unit/component suite and the full Chromium E2E suite locally. **Record the URL of the first passing CI run here.**

**Audit findings**

- There is no `/books/[id]` route, so nothing conflicts with `/books/[slug]`. Bookstore admin was already entirely under `/admin/bookstore/*`; the previous version of this document abbreviated those paths, which made them look like public routes.
- **Ambiguity fixed:** `/books/[slug]` sits beside the static `cart`, `catalog`, `checkout` and `orders`. Book slugs come from the title, so a listing titled "Checkout" would have been unreachable. The book editor now rejects those slugs (`RESERVED_BOOK_SLUGS` in `lib/bookstore.ts`); no route moved.
- `new` beside `[courseId]`, `[testId]` and `[bookId]` can't collide, because generated ids are prefixed (`c-…`, `t-…`, `b-…`).
- Dynamic pages read the browser's mock store, so an unknown id returns HTTP 200 with an in-page "not found" state. Unknown paths return a real 404. Both behaviours are asserted.
